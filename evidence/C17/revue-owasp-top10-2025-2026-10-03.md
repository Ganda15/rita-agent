## 3. Entrée par entrée

### A01:2025 Contrôle d'accès défaillant : 🟢 tenu, une réserve

**Ce qui est en place.** Une seule clé d'API, exigée par une dépendance posée **sur le routeur entier** des données (`api/main.py:207`) : une nouvelle route ne peut pas oublier la protection. `/briefing` et `/audit/mcp` l'exigent aussi ; `/health` seul est public et ne rend aucune donnée. Rôle PostgreSQL `rita_lecture` en lecture seule (`db/roles.sql`, 4 tests). La passerelle MCP passe par l'API et ne touche jamais la base.
**Preuves.** Tests `test_toute_route_donnees_est_protegee` et `test_sans_cle_l_acces_est_refuse` (`tests/test_api_donnees.py`). **En production le 03/10** : `/donnees/valeurs` sans clé et avec une fausse clé : **403** ; `POST /briefing` sans clé : **403**.
**Réserves.** (1) `/docs`, `/redoc` et `/openapi.json` répondent **200 sans clé** en production : la carte complète de l'API est publique, sans aucune donnée (**S2**). (2) Un seul niveau d'accès, choix d'une application mono-utilisateur (décision D10, à défendre par écrit : décision D1 du plan E4). (3) Le rôle `rita_lecture` existe mais aucun outil ne l'utilise encore.

### A02:2025 Mauvaise configuration de sécurité : 🔴 le point faible

**Ce qui est en place.** Conteneur de l'API non root (`USER rita`), système de fichiers en lecture seule, `no-new-privileges` ; la base de pré-production n'est pas publiée sur le réseau ; le front ne charge **aucune ressource externe ni aucun script en ligne** (vérifié), donc une politique de sécurité du contenu stricte est possible sans rien casser.
**Ce qui manque, mesuré en production le 03/10** : la réponse ne porte **aucun** en-tête de sécurité : ni `Content-Security-Policy`, ni `Strict-Transport-Security`, ni `X-Content-Type-Options`, ni `X-Frame-Options`, ni `Referrer-Policy`. Elle annonce `Server: uvicorn` et `Via: 1.1 Caddy` (**S1**). La documentation interactive est publique (**S2**).
**Mots de passe par défaut (S8).** `sources/database.py`, `db/importer.py` et `db/rgpd_purge.py` gardent une adresse de base par défaut avec le mot de passe `rita_dev_local` ; c'est **voulu et documenté** (elle vise le port 5432 pour échouer quand la configuration manque, au lieu de masquer l'absence, leçon d'INC-001). `db/docker-compose.yml` (développement) publie PostgreSQL sur toutes les interfaces avec ce même mot de passe ; `docker-compose.yml` (pré-production) a une valeur de secours `rita_preprod_local` si `POSTGRES_PASSWORD` manque. Aucun de ces fichiers ne sert la production ; à durcir quand même, parce qu'une valeur de secours est une porte ouverte documentée.

### A03:2025 Défaillances de la chaîne d'approvisionnement logicielle : 🟠 partiel

**En place.** L'image de l'API installe `requirements-api.txt`, **13 dépendances sur 13 épinglées** (`==`). Permissions par défaut des workflows : lecture seule (API GitHub). Aucun secret dans l'historique (§2).
**Manques (S7).** `requirements.txt` (développement et CI) : 13 lignes sur 18 sans version (carte #23) ; aucun hachage (`--require-hashes`) ; **alertes Dependabot désactivées** (l'API GitHub le dit) et aucun fichier `dependabot.yml` ; les actions GitHub sont épinglées par **étiquette** (`@v7`), pas par empreinte de commit, dont une action tierce (`anthropics/claude-code-action@v1`) qui reçoit `id-token: write` ; image de base `python:3.13-slim` non épinglée par empreinte ; pas d'inventaire des composants (SBOM).
**Un fournisseur de plus dans la chaîne** : le modèle de langage. Le banc C7 a montré que le Claude servi par OpenRouter vient d'Amazon Bedrock ([`../C7/preuve-benchmark-2026-10-03.md`](../C7/preuve-benchmark-2026-10-03.md), §10) : le texte du briefing traverse donc des hébergeurs que RITA ne choisit pas un par un.

### A04:2025 Défaillances cryptographiques : 🟢 tenu

**Mesuré en production le 03/10** : TLS **1.3** (`TLS_AES_128_GCM_SHA256`), **TLS 1.0 et 1.1 refusés**, certificat Let's Encrypt valide, HTTP redirigé vers HTTPS (308). Clé comparée par `secrets.compare_digest` (temps constant), longueur minimale de 16 caractères, API qui refuse de démarrer sans clé. Aucun mot de passe d'utilisateur n'est stocké. Côté navigateur, la clé vit dans `sessionStorage` (effacée à la fermeture de l'onglet), jamais dans un fichier du front (test).
**Points à surveiller.** (1) **Le certificat expire le 18/11/2026, avant le jury du 30/11** : Caddy renouvelle automatiquement, mais ce renouvellement n'a jamais été observé sur ce serveur ; à contrôler fin octobre (**S10**). (2) Pas d'en-tête HSTS (voir A02). (3) Le chiffrement des sauvegardes n'est pas documenté : non vérifié ici.

### A05:2025 Injection : 🟢 tenu, une réserve

**SQL.** Toutes les exécutions passent des paramètres liés (`%(nom)s`, `%s`). Trois endroits assemblent du texte SQL : `db/importer.py:222` et `:236` (un fragment **constant**, `CLE_LIGNE`) et `scripts/lister_articles.py:66` (des marqueurs `%(motifN)s` générés, les valeurs restant liées) : aucune entrée d'utilisateur n'atteint le texte de la requête. Les filtres de l'API sont bornés (`limite` entre 1 et 1 000, ticker de 1 à 16 caractères sur `/cotations`, série FRED contrôlée contre une liste fermée, modèle Pydantic fermé `extra="forbid"` sur `/audit/mcp`).
**Navigateur.** Les trois écrans écrivent par `textContent`, jamais `innerHTML` (trois tests). Le texte du modèle est traité comme une donnée.
**Journal.** Identifiant de requête accepté seulement s'il est sain (8 à 64 caractères sûrs), valeurs écrites avec `%r` (pas de fausse ligne de journal).
**Commandes.** Aucun `eval`, `exec`, `pickle`, `yaml.load` ni `shell=True` dans le code de l'application.
**Réserve, mesurée (S5).** `POST /briefing` prend `ticker: str` **sans longueur maximale** : un ticker de 5 000 caractères est écrit en entier dans le journal et renvoyé en entier (5 027 caractères) dans la réponse 502 ; une balise `<img src=x>` revient telle quelle dans le JSON, sans danger ici parce que l'écran l'affiche par `textContent`.
**Injection de prompt** (hors du Top 10 web, première entrée du Top 10 des applications de modèles de langage). Mesuré le 03/10 : garde-fou d'injection **70 %** de blocage sur 10 cas, 0 % de faux positifs ; garde-fou de sortie **70 %** sur 10, 0 % ; garde-fou d'entrée 100 % sur 5. Les deux premiers sont **sous le seuil de 85 %**, déclarés en `xfail` dans `tests/test_evals.py`, seuil jamais baissé (**S9**). Les phrases qui passent sont listées par les mesures (« une occasion à saisir », « mérite une place dans un portefeuille diversifié »).

### A06:2025 Conception non sécurisée : 🟠 partiel

**En place.** La contrainte AMF est dans le code, pas seulement dans le prompt : le garde-fou de sortie est en échec fermé (un doute = texte non diffusé). Les positions de l'utilisateur ne sont jamais envoyées au modèle (le scout ne lit que trois lectures de marché). La passerelle MCP n'a pas d'accès direct à la base. Le risque des trois ingrédients réunis (données privées, contenu non fiable, sortie vers l'extérieur) a été étudié en veille (S33, S34).
**Manques.** (1) **Aucune limite de débit (S3)** : celui qui tient la clé peut déclencher autant d'appels payants qu'il veut (OWASP API4:2023, consommation de ressources non bornée). (2) **Pas de modèle de menace écrit** dans le dépôt : il existe en morceaux dans la veille, pas comme un document. (3) Seize indicateurs spécifiés, treize envoyés au modèle : le choix de ne pas envoyer les positions est un choix de confidentialité, à écrire comme tel.

### A07:2025 Défaillances d'authentification : 🟠 partiel

**En place.** Plus de clé par défaut depuis le 18/08 (INC-001, test `test_l_api_refuse_de_servir_sans_cle_configuree`) ; longueur minimale ; comparaison à temps constant ; une clé refusée est oubliée par l'écran et redemandée.
**Manques.** Une seule clé statique partagée, sans expiration, sans procédure de rotation testée ; **aucune limite aux essais** (S3) ; aucun journal des refus (S4) ; l'écran briefing mémorise la clé avant de savoir si elle fonctionne (carte #73).

### A08:2025 Défaillances d'intégrité des logiciels ou des données : 🟢 tenu

**En place.** Règles GitHub : `main` ne change que par une pull request avec `pytest`, `evals` et la revue verts ; les tags `livrable-*` ne peuvent être ni déplacés ni supprimés ([`../C19/preuve-protection-main-2026-10-03.md`](../C19/preuve-protection-main-2026-10-03.md)). L'image n'est publiée qu'après sa vérification, et seulement sur un tag. En base : écriture par `db/importer.py` et `pipelines/ingest.py` seulement, 12 contraintes `CHECK` dans `db/schema.sql` (trois de plus dans les migrations du 03/10), articles marqués par le garde-fou d'injection avant d'entrer dans la recherche.
**Limites.** Image non signée ; actions épinglées par étiquette (voir A03).

### A09:2025 Défaillances de journalisation et d'alerte : 🟠 partiel

**En place.** Un identifiant par requête dans l'en-tête, dans chaque ligne de journal et comme identifiant de trace Langfuse, y compris sur un 500 (test `test_une_erreur_inattendue_500_porte_aussi_l_identifiant`). Une ligne par briefing servi, une par refus du garde-fou, jamais le texte. Traces Langfuse ; un workflow ouvre une issue sur une alerte Langfuse.
**Manques.** (1) **Les refus d'authentification (403) ne laissent aucune ligne** (S4) : une tentative de force brute serait invisible. (2) **Aucune alerte quand la chaîne d'intégration continue est rouge** : INC-007 l'a montré, dix exécutions rouges en 1 h 20 sans que personne le sache. (3) Les alertes Langfuse attendent leur configuration par Era. (4) Un ticker sans longueur maximale peut remplir le journal (S5).

### A10:2025 Mauvaise gestion des conditions exceptionnelles : 🟢 tenu, une réserve

**En place.** Toute exception imprévue devient un 500 générique, avec l'identifiant de requête, le détail allant au journal seulement (test). Mesuré le 03/10 : quand **tous** les fournisseurs échouent, le client reçoit `{"detail": "Erreur interne. Identifiant de requete : …"}` et **l'adresse interne du fournisseur ne fuit pas**. La cascade passe d'un fournisseur au suivant ; le garde-fou de sortie échoue fermé ; un indicateur absent s'affiche « — », jamais 0 ; une panne d'un lot d'indicateurs ne fait pas tomber l'autre.
**Réserve (S6).** Cette panne de tous les fournisseurs donne **500, pas 502** : le message « Aucun fournisseur de modèle ne répond pour le moment » prévu par l'écran briefing **n'apparaît jamais** ; l'utilisateur lit « Erreur 500 — le serveur n'a pas pu répondre. ». Sûr, mais moins clair. La spécification US-3 du 03/10 affirmait l'inverse ; elle est corrigée par une note datée (§6).

## 7. Ce que cette revue n'est pas

Une revue de code faite par l'auteur du code, appuyée sur des mesures et des sondes, sans outil d'analyse automatique ni test d'intrusion. Elle ne prouve pas l'absence de faille ; elle dit, pour chaque entrée, ce qui est en place, avec quelle preuve, et ce qui manque.

*Un document qui ne signale aucune faiblesse n'est pas crédible devant un jury.*

## 📖 Glossaire

| Terme | En clair |
|---|---|
| **OWASP Top 10** | liste de référence des dix risques de sécurité les plus courants des applications web, revue tous les quatre ans environ ; l'édition 2025 est la huitième |
| **Chaîne d'approvisionnement logicielle** | tout ce dont l'application dépend sans l'avoir écrit : bibliothèques, images Docker, actions GitHub, services de modèle |
| **En-têtes de sécurité** | consignes envoyées par le serveur au navigateur : CSP (d'où peuvent venir les scripts), HSTS (toujours HTTPS), `nosniff` (ne pas deviner le type d'un fichier) |
| **CSP** | Content Security Policy : la liste des origines autorisées pour les scripts, styles et images d'une page |
| **Limitation de débit** | nombre maximal d'appels par période ; au-delà, l'API répond 429 |
| **Temps constant** | comparaison dont la durée ne dépend pas du nombre de caractères justes : elle ne renseigne pas un attaquant |
| **Échec fermé** | en cas de doute ou de panne, le système refuse au lieu de laisser passer |
| **Dependabot** | service de GitHub qui signale les dépendances ayant une faille connue |
| **Épingler par empreinte** | désigner une version par son identifiant unique (hachage), qui ne peut pas être déplacé, plutôt que par une étiquette qui peut l'être |
| **Injection de prompt** | texte qui tente de faire désobéir le modèle à ses consignes, par exemple caché dans un article |
| **Force brute** | essayer des clés au hasard jusqu'à tomber sur la bonne |
